# Week View Implementation Plan

**Date:** 2026-09-02
**Supersedes:** nothing
**Superseded by:** nothing

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the weekly rollup — a grid of tickets against Monday–Sunday with push state on every
cell — and change the rail from "always today" to "the period of the view you are in".

**Architecture:** A new `GET /api/week` returns a pre-aggregated grid, so the browser never sums or
decides a day. The rail stops fetching today unconditionally and instead renders whatever period the
mounted view hands it, pushing the days that period contains. Today's push-report renderer is
extracted so both views share the one implementation of a report whose `store_failed` branch is a
safety property.

**Tech Stack:** Go standard library with `httptest` and `testing/fstest`; vanilla TypeScript with
`node --test` for pure modules and Playwright for anything touching the DOM; Tailwind v4.

**Spec:** `docs/superpowers/specs/2026-09-02-week-view-design.md`. Read it before Task 1 — it holds
the ten decisions and their reasoning. This plan implements it and does not re-argue it.

## Global Constraints

- **Local development runs in Docker.** There is no Go, Node or npm on the host. Every command goes
  through `make` or `docker compose`. Never run `go`, `node`, `npm`, `npx`, `tsc` or `prettier`
  bare.
- **Do not run `make fmt`.** It is write-only and rewrites files that are already committed (#74).
- **No JavaScript frameworks.** Vanilla TypeScript. No new runtime dependency; the approved
  non-stdlib Go set is `modernc.org/sqlite` and `golang.org/x/sync` and this ticket adds to neither.
- **`tsconfig.json` is not weakened.** `strict` with `noUncheckedIndexedAccess` stays. No `any`, no
  `as any`, no non-null assertion, no `eslint-disable`. The type error is usually right.
- **Reusable UI is a light-DOM WebComponent named `that-*`.** No shadow DOM.
- **Format carries meaning.** `timerFigure` (`HH:MM`) is for timers only. Every figure this ticket
  renders is a sum, so every one of them is `totalFigure` (`Nh Nm`). A colon anywhere in the Week
  view is a bug.
- **Never parse a `YYYY-MM-DD` string with `new Date()`.** It is parsed as UTC and rendered in the
  browser's zone, which shifts the day for anyone west of Greenwich. Split the string.
- **The browser never decides which day an entry belongs to.** The server stamps `day`; the browser
  echoes it back. Nothing here may derive a day from the browser clock.
- **Push state is derived, never stored.** Reuse `pushStateOf` (`internal/server/entries.go:44`).
- **A dirty entry is not pushable.** `handlePushDay` skips every entry whose state is not
  `unpushed` (`internal/server/push.go:132`). Making dirty entries pushable is #10.
- **Comments are few and earn their place** with a non-obvious "why". Do not narrate the next line.
- **Table-driven tests with `t.Run` subtests**, `httptest` and `testing/fstest` rather than real
  network or filesystem. No test contacts a real Jira instance.

/**
 * A week's range, as the rail's period label reads it — `7–13 Sep`.
 *
 * Both bounds come from the server's own response, so this never decides which
 * week anything is in; it only renders one. It splits the ISO strings rather
 * than parsing them, because `new Date("2026-09-07")` is UTC midnight and every
 * getter reads it in the browser's zone — one timezone west and the label is off
 * by a day. Splitting has no zone to be wrong about.
 */
const MONTHS = [
  "Jan", "Feb", "Mar", "Apr", "May", "Jun",
  "Jul", "Aug", "Sep", "Oct", "Nov", "Dec",
] as const;

interface Parts {
  year: string;
  month: string;
  day: number;
}

function partsOf(iso: string): Parts {
  const [year = "", month = "", day = ""] = iso.split("-");

  return { year, month: MONTHS[Number(month) - 1] ?? month, day: Number(day) };
}

export function weekLabel(start: string, end: string): string {
  const from = partsOf(start);
  const to = partsOf(end);

  if (from.year !== to.year) {
    return `${String(from.day)} ${from.month} ${from.year} – ${String(to.day)} ${to.month} ${to.year}`;
  }
  if (from.month !== to.month) {
    return `${String(from.day)} ${from.month} – ${String(to.day)} ${to.month}`;
  }

  return `${String(from.day)}–${String(to.day)} ${from.month}`;
}
```

## Task 2: `worstPushState` — the aggregation rule

A cell sums entries whose push states can disagree. The spec's rule is **worst wins**, ordered
unpushed > dirty > pushed. This is the piece a plausible refactor is most likely to get backwards,
so it is written and tested alone before any handler uses it.

// entryInState builds the minimal entry that pushStateOf will read as `state`.
// updated is only meaningful for "dirty", where it must be after pushed.
func entryInState(state string) store.Entry {
	pushed := time.Date(2026, 9, 9, 10, 0, 0, 0, time.UTC)

	switch state {
	case "unpushed":
		return store.Entry{UpdatedAt: pushed}
	case "pushed":
		return store.Entry{WorklogID: "1", PushedAt: &pushed, UpdatedAt: pushed}
	case "dirty":
		return store.Entry{WorklogID: "1", PushedAt: &pushed, UpdatedAt: pushed.Add(time.Hour)}
	}

	panic("unknown state " + state)
}

func TestWorstPushState(t *testing.T) {
	cases := []struct {
		name  string
		given []string
		want  string
	}{
		{"no entries at all", nil, ""},
		{"one unpushed", []string{"unpushed"}, "unpushed"},
		{"one pushed", []string{"pushed"}, "pushed"},
		{"one dirty", []string{"dirty"}, "dirty"},
		{"all pushed", []string{"pushed", "pushed"}, "pushed"},
		{"pushed and unpushed reads unpushed", []string{"pushed", "unpushed"}, "unpushed"},
		{"unpushed and pushed, order does not matter", []string{"unpushed", "pushed"}, "unpushed"},
		{"pushed and dirty reads dirty", []string{"pushed", "dirty"}, "dirty"},
		{"dirty and unpushed reads unpushed", []string{"dirty", "unpushed"}, "unpushed"},
		{"unpushed beats dirty whatever the order", []string{"unpushed", "dirty"}, "unpushed"},

package server

import "forge/internal/store"

// pushStateRank orders the three derived states by how much they still need
// doing. A cell is a sum of entries that can disagree, and the marker it shows
// is the worst of them — imprecise, and never falsely reassuring, which is the
// side to err on when the reader is about to submit a timesheet.
//
// unpushed outranks dirty deliberately: dirty time is in Jira and merely stale,
// unpushed time is not there at all.
var pushStateRank = map[string]int{"pushed": 0, "dirty": 1, "unpushed": 2}

// worstPushState reports the state a cell or a day shows, or nil when it holds
// no entries at all — which is what makes the JSON field null rather than a
// fourth state the browser would have to know about.
func worstPushState(entries []store.Entry) *string {
	if len(entries) == 0 {
		return nil
	}

	worst := pushStateOf(entries[0])
	for _, entry := range entries[1:] {
		if state := pushStateOf(entry); pushStateRank[state] > pushStateRank[worst] {
			worst = state
		}
	}

	return &worst
}
```

// handleWeek answers with a Monday-to-Sunday rollup. start defaults to the
// current week's Monday resolved in THAT_TIMEZONE, so the browser never computes
// one — the same reason handleListEntries defaults its bounds to today.
func (s *Server) handleWeek(w http.ResponseWriter, r *http.Request) {
	today := s.now().In(s.cfg.Location)
	start, ok := dayParam(w, r, "start", mondayOf(today))
	if !ok {
		return
	}

	// Parsed rather than trusted: dayParam proves it is a date, not that it is a
	// Monday. A start that is not one is rejected rather than snapped to its own
	// week's Monday, so two different values cannot return identical bodies.
	startAt, err := time.ParseInLocation(dayLayout, start, s.cfg.Location)
	if err != nil || startAt.Weekday() != time.Monday {
		writeError(w, http.StatusBadRequest, "start_not_monday",
			"start must be a Monday, of the form YYYY-MM-DD")
		return
	}
	end := startAt.AddDate(0, 0, daysInWeek-1).Format(dayLayout)

	// Instances first — see instanceIndex on why this order is load-bearing.
	instances, positions, ok := s.instanceIndex(w, r)
	if !ok {
		return
	}

	entries, err := s.db.EntriesForDay(r.Context(), start, end)
	if err != nil {
		writeError(w, http.StatusInternalServerError, "store_failed", "could not read the logged time")
		return
	}

	writeJSON(w, http.StatusOK, rollUp(startAt, entries, instances, positions))
}

// mondayOf is the local date of the Monday on or before t. Go's Weekday puts
// Sunday at 0, so a Sunday is six days after its Monday rather than one before
// the next — the off-by-one this exists to state once.
func mondayOf(t time.Time) string {
	back := (int(t.Weekday()) + 6) % daysInWeek

	return t.AddDate(0, 0, -back).Format(dayLayout)
}

// rowKey identifies a grid row. The same issue key in two instances is two rows,
// which is why the instance is half of the key.
type rowKey struct {
	instanceID int64
	issueKey   string
}

func rollUp(
	startAt time.Time,
	entries []store.Entry,
	instances map[int64]store.Instance,
	positions map[int64]int,
) weekRollupDTO {
	days := make([]string, daysInWeek)
	index := make(map[string]int, daysInWeek)
	for i := range days {
		days[i] = startAt.AddDate(0, 0, i).Format(dayLayout)
		index[days[i]] = i
	}

	byCell := make(map[rowKey][][]store.Entry)
	byDay := make([][]store.Entry, daysInWeek)
	for _, entry := range entries {
		at, ok := index[entry.Day]
		if !ok {
			continue
		}
		key := rowKey{instanceID: entry.InstanceID, issueKey: entry.IssueKey}
		if _, seen := byCell[key]; !seen {
			byCell[key] = make([][]store.Entry, daysInWeek)
		}
		byCell[key][at] = append(byCell[key][at], entry)
		byDay[at] = append(byDay[at], entry)
	}

	keys := make([]rowKey, 0, len(byCell))
	for key := range byCell {
		keys = append(keys, key)
	}
	sort.Slice(keys, func(i, j int) bool {
		left, right := positions[keys[i].instanceID], positions[keys[j].instanceID]
		if left != right {
			return left < right
		}

		return keys[i].issueKey < keys[j].issueKey
	})

	rollup := weekRollupDTO{
		Start: days[0],
		End:   days[daysInWeek-1],
		Days:  make([]weekDayDTO, daysInWeek),
		Rows:  make([]weekRowDTO, 0, len(keys)),
	}

	for i, day := range days {
		seconds := 0
		for _, entry := range byDay[i] {
			seconds += entry.Seconds
		}
		rollup.Days[i] = weekDayDTO{Day: day, Seconds: seconds, PushState: worstPushState(byDay[i])}
		rollup.Seconds += seconds
	}

	for _, key := range keys {
		row := weekRowDTO{
			InstanceID:       key.instanceID,
			InstanceName:     instances[key.instanceID].Name,
			InstancePosition: positions[key.instanceID],
			IssueKey:         key.issueKey,
			Cells:            make([]weekCellDTO, daysInWeek),
		}
		for i, cell := range byCell[key] {
			seconds := 0
			for _, entry := range cell {
				seconds += entry.Seconds
			}
			row.Cells[i] = weekCellDTO{Seconds: seconds, PushState: worstPushState(cell)}
			row.Seconds += seconds
		}
		rollup.Rows = append(rollup.Rows, row)
	}

	return rollup
}

import type { PushResponse, PushResult } from "./types";

/**
 * The one rendering of a finished push, shared by every view that can trigger
 * one. Not duplicated per view on purpose: the store_failed branch below is a
 * safety property, and a second copy is a second chance to word it wrongly.
 */
export interface PushReportOptions {
  /** Prefix each failure with its day. A week push covers several; a day push does not. */
  nameDays?: boolean;
}

/**
 * Names every entry that did not reach Jira. A count alone would be the blanket
 * status the spec calls a defect: with several entries against one ticket, "2
 * failed" does not say which two.
 *
 * A failure whose code is `store_failed` is reported apart from the rest, and
 * that split is the point of reading the code at all. Those entries did reach
 * Jira — only the local record of them did not — so the retry that is right for
 * every other failure is exactly wrong for them: pressing Push again logs the
 * time in Jira twice, and nothing in this app can undo it.
 */
export function pushReportNodes(
  responses: PushResponse[],
  options: PushReportOptions = {},
): Node[] {
  const all = responses.flatMap((response) =>
    response.results.map((result) => ({ day: response.day, result })),
  );
  const failed = all.filter((line) => line.result.status === "failed");
  const pushed = all.filter((line) => line.result.status === "pushed");

  if (failed.length === 0) {
    return [
      alertFor(
        "success",
        `Pushed ${String(pushed.length)} ${pushed.length === 1 ? "entry" : "entries"} to Jira.`,
      ),
    ];
  }

  const stranded = failed.filter((line) => line.result.error?.code === "store_failed");
  const retryable = failed.filter((line) => line.result.error?.code !== "store_failed");
  const nodes: Node[] = [];

  if (retryable.length > 0) {
    nodes.push(
      alertFor(
        "warning",
        `${String(retryable.length)} of ${String(all.length)} entries did not ` +
          "reach Jira. Press Push to Jira again to retry them.",
      ),
      failureList(
        retryable.map(
          (line) =>
            label(line.day, line.result, options) +
            ` — ${line.result.error?.message ?? "unknown error"}`,
        ),
      ),
    );
  }

  if (stranded.length > 0) {
    nodes.push(
      alertFor(
        "error",
        `${String(stranded.length)} ${stranded.length === 1 ? "entry" : "entries"} reached Jira ` +
          "but could not be recorded here. Check the issue in Jira before pushing again — " +
          "pushing now would log the time twice.",
      ),
      failureList(stranded.map((line) => label(line.day, line.result, options))),
    );
  }

  return nodes;
}

/** A week push covers several days, so "RID-204 failed" does not say where to look. */
function label(day: string, result: PushResult, options: PushReportOptions): string {
  return options.nameDays === true ? `${day} · ${result.issueKey}` : result.issueKey;
}

/**
 * A sibling of the alert it follows, never a child of it: that-alert renders by
 * calling this.replaceChildren(mark, message), so anything appended inside it
 * is discarded the next time an attribute changes.
 */
function failureList(lines: string[]): HTMLElement {
  const list = document.createElement("ul");
  list.className = "mt-2 ml-6 space-y-1 text-sm";
  for (const line of lines) {
    const item = document.createElement("li");
    item.textContent = line;
    list.append(item);
  }

  return list;
}

function alertFor(tone: string, message: string): HTMLElement {
  const alert = document.createElement("that-alert");
  alert.setAttribute("tone", tone);
  alert.setAttribute("message", message);

  return alert;
}

- [ ] **Step 2: Write the view**

Create `web/src/views/week.ts`. Build it with the existing Tailwind utilities and `that-card`; read

**The cell renderer carries every rule that matters, so it is given here in full.** The table
assembly around it is ordinary DOM building and is specified as requirements below.

```ts
import type { WeekCell } from "../types";
import { totalFigure } from "../format";

/**
 * One cell. Three things are load-bearing here and none of them is obvious:
 *
 * `totalFigure`, never `timerFigure` — format.ts reserves the colon for a
 * timer, and a colon somewhere you cannot press play is a bug rather than a
 * formatting preference. Every figure in a rollup is a sum.
 *
 * An em dash for an empty cell, not `0h 00m` — a zero is a measurement, and a
 * cell with no entries has not measured anything.
 *
 * The marker is inline with no reserved width. The column is right-aligned, so
 * the figure ends at the same edge either way and the marker hangs off to the
 * left; a reserved gutter would fix a drift that does not happen.
 */
function cellNode(cell: WeekCell): HTMLTableCellElement {
  const td = document.createElement("td");
  td.className = "px-2 py-1.5 text-right";

  if (cell.seconds === 0) {
    td.className += " text-ink-muted";
    td.textContent = "—";

    return td;
  }

  if (cell.pushState === "unpushed" || cell.pushState === "dirty") {
    const mark = document.createElement("span");
    // Filled against hollow, so the two states differ in shape as well as hue.
    mark.className =
      cell.pushState === "unpushed"
        ? "mr-1.5 inline-block size-1.5 rounded-full bg-unpushed align-[1px]"
        : "mr-1.5 inline-block size-1.5 rounded-full border-[1.5px] border-dirty align-[1px]";
    mark.setAttribute("aria-hidden", "true");
    td.append(mark);

    const state = document.createElement("span");
    state.className = "sr-only";
    // Named for a reader who cannot see the marker. "Dirty" is the code's word,
    // not a person's.
    state.textContent =
      cell.pushState === "unpushed" ? "not pushed to Jira, " : "edited since it was pushed, ";
    td.append(state);
  }

  td.append(document.createTextNode(totalFigure(cell.seconds)));

  return td;
}
```

`bg-unpushed` and `border-dirty` are new theme colours: add them to `@theme` in
`web/src/styles.css` beside the existing state colours, amber 85 and the primary 330 respectively.
Task 9 records the second one in the design language.

Requirements the rest of the view must meet, each traceable to the spec:

- The grid is a `<table>`: a header row of `Ticket`, seven day columns and `Total`; a body row per
  rollup row; a footer of day totals and the week total.
- **Every figure is `totalFigure`.** A cell with `seconds === 0` renders an em dash, not `0h 00m`.
- Each body row begins with an instance dot coloured by `instancePosition`, then the issue key. The
  instance name is available to assistive technology, never hue alone.
- A cell with `pushState === "unpushed"` carries a filled marker before the figure; `"dirty"` a
  hollow ring; `"pushed"` and `null` carry nothing. The marker is inline — do not reserve a gutter,
  the column is right-aligned and the digits already align.
- The table carries `that-tnum` (or `font-variant-numeric: tabular-nums`) throughout.
- A header with the week label from `weekLabel(rollup.start, rollup.end)`, a previous and a next
  control, and a "This week" control. Each navigates via `navigate("/week?start=…")`, where the
  target start comes from **the response**, not from browser date arithmetic — see Step 3.
- An empty week renders an empty state rather than an empty table.
- The report region sits **below** the table and is `hidden` while empty, for the same reason
  Today's is: an empty box still claims a `space-y-*` margin.
- On mount, `setRailPeriod({ label: \`Week · ${weekLabel(start, end)}\`, viewPath: "/week", range: { from: rollup.start, to: rollup.end }, pushHeading: "Push this week's time to Jira?" })`.
- `onPushReported((responses) => …)` renders `pushReportNodes(responses, { nameDays: true })` into
  the report region, and re-reads the rollup so the markers settle. Register its unsubscribe with
  `registerTeardown`.
