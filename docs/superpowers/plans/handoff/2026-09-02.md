## Two new tickets from the owner

Both asked for directly, so both were created at `status/needs-refinement` —
the asking was the approval — and both are `enhancement`.

**#83, sorting the assigned issue listing on any displayed column.** Refinement
has real questions waiting. The rows are not a table, so there is no column
header to click and the control has to be designed. The order today is Jira's,
not the app's: `assignedJQL` ends `ORDER BY updated DESC`, and `updated` is not
one of the four values a row displays. `SearchAssigned` pages to exhaustion, so
the browser holds the whole assigned set and client-side sorting would sort all
of it rather than a first page.

**#84, searching for any issue and logging against it without pinning.** The
use case is time spent on discussions and reviews, where pinning makes a
fixture out of a one-off. Most of the machinery exists: `/api/issues/search`
is implemented and fanned out, and `that-entry-dialog` already takes an
`EntryTicket` rather than anything pin-shaped. The gap is a route from a search
result to the dialog that skips the pin. The catch is that the endpoint was
built for a pin type-ahead: it matches on summary only, excludes
`statusCategory != Done`, and caps at ten results per instance. All three are
wrong for finding one closed ticket by key, and widening them changes what the
pin picker offers.

## A loose end that was not one, and the reading error behind it

`handoff-2026-09-01` was first read as pushed but with no pull request open, and
written up here as work at risk. **That was wrong.** The branch merged as PR #82,
which put remote `main` at `0c1dcfc`, and Codeberg deleted the branch on merge.
Nothing was ever at risk.

The error is worth keeping because it will recur. 1Password was not running, so
`git fetch` could not authenticate — and a failed fetch does not blank the
`codeberg/*` refs, it leaves them frozen at the last successful fetch. Local git
therefore answered confidently and wrongly: a tracking ref for a branch the forge
no longer has, and an ahead-count against a stale `main`. `tea` and the HTTPS API
were working the whole time, because they carry a token rather than the SSH key.
**Checking the forge over the API is what corrected it**, and that is now an
environment note in `handoff.md`.

Second-order lesson: a remote branch that has vanished usually means its pull
request merged. Reading it as a lost push is the pessimistic guess, and it was
the wrong one here.

## `retro-skill` opened as PR #85

The branch had sat since before the forge move. Getting it to a mergeable state
took two things the handoff had predicted and one it had not.

The `CLAUDE.md` hunk conflicted, because that file has since gained the handoff
split and the eod paragraph. The retro paragraph now sits after the eod one, so
the skill invocations read as a group.

The unpredicted part was the body: **every command in the skill was `gh`**, which
has no authority on Codeberg. Ported to `tea`, with each replacement run against
the repository rather than guessed. That turned up three limits now written into
the skill: `tea pr list` has no `--state merged`, so merged pull requests are
separated by the `state` field in its JSON; that JSON flattens `labels` to a
comma-joined string rather than a list, which breaks code that iterates it; and
the plain HTTPS API is richer than either and needs no extra credential.

The skill also gained this morning's lesson, since a retro is exactly the thing
that would trip on it: check the forge, not local git.

`worktrees-without-the-tax` is now the only branch pushed with no pull request.
