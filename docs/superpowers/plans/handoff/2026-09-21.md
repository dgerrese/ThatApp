## #134 refined: the Chromium crash is a Playwright version bug

The owner chose to leave #66 blocked and start #134. Refinement meant measuring it rather than
describing it, and the measurement settled the ticket.

**Fifty full `make test-e2e` runs on `main` at `b623295`**, each ~70s:

| Playwright | runs | crashes |
|---|---|---|
| 1.62.1 | 20 | 5 (25%) |
| 1.63.0 | 30 | 0 |

The 1.62.1 total includes a ten-run control taken *after* the thirty clean runs, which crashed three
times — so machine drift is excluded and the version is the variable. If the old rate held, thirty
clean runs is a 1-in-5,600 coincidence.

**All five crashes were byte-identical**: `SEGV_MAPERR 0x1b0`, same stack offsets frame for frame,
same registers, dying in the *browser* process inside `browser.newContext`. Only the victim test
differed (three distinct ones). So the intake framing was wrong: this is not a family of flaky
failures, it is one deterministic fault with a random bystander. The body now says so.

Two things ruled out along the way, both worth not re-testing:

- **Shared memory.** `ipc: host` is already set *and* Playwright's own default args carry
  `--disable-dev-shm-usage`. Covered twice.
- **"Never seen in CI" as evidence.** `retries: 1` in CI means a crashed test is retried and passes,
  so the run goes green. The CI rate is unknown, not zero.

**Never tested:** whether the local worker count (10, against CI's 4) raises the rate. The version
bump made it moot. It is recorded as the next hypothesis if the bump does not hold, and is named
out of scope on the ticket rather than silently dropped.

One methodological trap, for whoever measures a version next: `npx playwright install` **prunes**
browser builds the current version does not use. Installing 1.63's browsers deleted 1.62.1's from
that container, so reverting with `npm ci` alone produced 524 "executable doesn't exist" failures
that looked like a catastrophic control. Run the control in a fresh container from the image instead.

#134 is refined and at `status/todo`. The fix is a one-line version bump in
`.claude/e2e/package.json` plus its lockfile; the suite passes unchanged on 1.63.0, 513/11/0.
