mode. It is **not** a repo problem: `fs.inotify.max_user_instances` is **128** on this machine and

`docker compose up -d --no-deps app`. The dev build tag reads assets from disk, so the app serves

needs a rebuild rather than appearing by itself.

**The fix needs root and is the owner's:** raise `fs.inotify.max_user_instances`, or stop the other
project's containers. Seen the same day as Task 11's "transient inotify exhaustion", which was the
same cause.

### What the reviews caught that the tasks could not

**The whole-branch review found a Critical defect for the fourth time in this project's life**, and
again it was two correct changes meeting. Task 5's fix round added a paint-skip: if a re-read comes
back with the same rollup and the same failure marks, do not repaint. `show()`'s error path replaces
the grid with an alert but left the paint record untouched. So after any failed read, a retry
returning identical data repainted nothing and the alert stayed until the user navigated away —
and identical retries are the normal case, not a contrived one. The implementer's stated reason the
skip was safe was true and insufficient: it reasoned about what the render path *reads* and never
considered that something else *writes* to the same grid.

**A test that documented behaviour the branch had removed.** Task 5 changed when failure marks are
consumed; a pre-existing test still described the old lifetime and passed only because its second
push overwrote the failure set. It would have passed equally if marks were preserved for ever.
Nothing in the suite exercised the consumption rule until the fix wave rewrote it.

**The empty-string day.** `rollup.days[index]?.day ?? ""` had been harmless when it only degraded an
aria-label. Once the day started travelling with the dialog, `""` was not `undefined`, so the dialog
read itself as scoped: a nonsense day line, a ranged read the server resolved to today, and a create
posting an empty day — naming one day while writing to another. One token at the call site closed
it, and closed a second deferred finding with it.
