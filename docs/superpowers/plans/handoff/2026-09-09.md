## `make up` cannot start its watcher on this host right now

`make up` fails with `Error: EMFILE: too many open files, watch '.'` from `web/build.mjs`'s watch
mode. It is **not** a repo problem: `fs.inotify.max_user_instances` is **128** on this machine and
about 162 inotify instances are already in use, mostly by another project's containers
(`v4-dash-*`, `docker-hoster`). The watcher cannot get an instance, `web` exits 1, and `app` refuses
to start because it depends on `web` being healthy.

**The workaround, which does not need root:** `make build-web` once, then
`docker compose up -d --no-deps app`. The dev build tag reads assets from disk, so the app serves
the built frontend at `localhost:8080` with no watcher at all. The cost is that a frontend change
needs a rebuild rather than appearing by itself.

**The fix needs root and is the owner's:** raise `fs.inotify.max_user_instances`, or stop the other
project's containers. Seen the same day as Task 11's "transient inotify exhaustion", which was the
same cause.
