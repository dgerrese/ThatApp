# 2026-09-04 — light mode, judged for the first time

The day had one question in it, left at sign-off the evening before: *the hover effects need another
look, in light mode*. Answering it properly turned into the first honest look at the light theme, and
it cost three defects and gained three rules.

## Where the day started

PR #96, the 2026-09-03 handoff, merged at 11:22. Remote `main` moved to `415f139`. The board was
clean — 28 open issues, every one carrying exactly one `status/*` label, nothing closed carrying one.

**A small trap worth knowing:** `tea issues list --output json` prints only the **first** label per
issue, so a board audit run through it reports most tickets as having no status at all. The API
endpoint returns the full set. The first read of the morning was wrong for exactly this reason.

## The hover wash

The prototype from 2026-09-03 was **dark only**, so there was nothing to look at. Judging the wash on
white meant building the light ground first.

Three strengths were put on paper-white beside the dark reference — 11%, 8% and 6% of ink — with the
real surfaces on each: the duration control, the pin, the week cells and the search rows.

**11% won unchanged.** The arithmetic had already said it should. The same mix lifts the dark card by
`0.081` in OKLab lightness and darkens the light card by `0.088`, which is as close to even as a
single formula gets. The reason to look anyway was that dark-on-light reads heavier than light-on-dark
at the same distance, and no measurement settles that.

**The wash had no token at all.** It existed only in the prototype, so the one number the decision
rested on lived in a file nothing read as authoritative. It now sits in the language beside
`--color-hover-rail`.

## Elevation, which the language never had

With the full app rendered light, the owner's first reaction was that the card shadows were far too
strong. They were: every shadow in the prototype was chosen by hand at the moment it was needed, on a
dark ground, in black at `0.4` to `0.75` alpha. **Neither edition of the visual language said anything
about depth.**

Three treatments were built on the light ground:

| Treatment | Outcome |
| --- | --- |
| Hairline plus a whisper of shadow | **Chosen** |
| The same shadows with their ink cut to a twentieth | Too faint to define a card, too vague to rank surfaces |
| A hairline and no shadow at all | Crispest and closest to the brief, but a floating search panel needs to read as *above* |

Light needs one or the other, because a card on the light ground is `0.995` against a `0.972` page —
a distance of 0.023. Dark has twice that separation and its shadows carry the rest. So the rule came
out **per theme**, which is the first thing in the language that is.

The scrim behind an open dialog was left alone deliberately. Half-opaque black on a white page is a
question about modality rather than depth.

## Two defects the light ground exposed

**The dialogs had no ink colour.** Both the entries dialog and Settings are siblings of the viewport
rather than children of it, and the viewport was the only thing declaring one — so they inherited the
host page's text colour. On the dark ground that inherited colour is light, the sheet is dark, and it
looks exactly right. On white the same text nearly vanished, and only the elements naming their own
colour survived.

This is the **fourth trap** in `2026-09-03-today-and-week-design.md` and the first that dark could
hide. It also has a live consequence for the build: the real dialog is a native `<dialog>` in the top
layer, which does not inherit from the view that opened it either.

**The cog's hover box escaped the rail's gutter.** A negative right margin pulled the glyph out to the
content edge and took the 34px wash with it, eight pixels into a fourteen-pixel gutter. The Add button
in Settings had already solved the same problem the other way — by matching the region's padding — and
that comment was the only place the rule existed. It is now in the language.

The owner kept one exception on sight: a table row's trailing icon button still overhangs its card.

**Also fixed:** *No comment* in the entries dialog was drawn in `--color-ink-faint`, which the design
document already called *muted* and which the language says in its own words is a mark colour that
fails the text floor in both themes.

## Notes on the day's tooling

- **The design session ran on the local browser companion**, as the standing decision requires. Files
  live under `.superpowers/brainstorm/`, which is gitignored — so the light rendering would have been
  lost. That is why the prototype itself was updated to carry both themes rather than leaving the
  light view in a scratch directory.
- **`git fetch --all` failed once** with `Permission denied (publickey)` while `git ls-remote` and a
  plain `git fetch codeberg` both worked minutes later against the same single remote. It cost a
  wrong claim to the owner that pushing was blocked. Treat one failure as transient and retry the
  narrower command before reporting a blocker.
- **Playwright's MCP browser is unusable on this machine** — it looks for Chrome at

  connected. There is no way to screenshot a page from this session; the owner is the only pair of
