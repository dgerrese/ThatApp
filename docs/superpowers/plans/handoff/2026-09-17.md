# 2026-09-17

## #122 shipped, and the first release is out

**The owner merged #148 and #149.** #122 closed with `status/in-progress` still on it, the seventh
time a merge has left one behind; it was stripped by hand.

**Before the merge**, PR #148's CI was confirmed green at `f02d84b`: the release dry run took 3m30s
against the ten-minute cap. On that evidence two criteria were ticked on #122: the pull-request dry
run, and the image holding only the binary and the CA bundle, which the script checks with
`crane export` on the pushed image.

**Cutting the release took three things nobody had written down.**
- The `RELEASE_TOKEN` secret: a personal token with *package: read and write* only, stored under
  the repository's Actions secrets.
- **Releases were disabled on the repository**, so `/releases/new` returned 404. Packages were
  disabled too. The owner enabled both under the unit settings, then tagged `v2026.38.1` on
  `2a90db9` with *Create tag only*.
- **The tag's run was invisible at first.** `actions/tasks` lists only jobs that have started, so a
  three-minute poll saw nothing. `actions/runs` showed run 108 queued behind the two `main` merge
  runs. It waited from 15:27 to 15:56 and then took 3m18s.

**Verified after the release:** the registry served the index for `2026.38.1` and `latest`
(amd64 + arm64) to an anonymous token. `docker pull` succeeded on this machine, which has no Docker
credentials. The amd64 image then ran under throwaway names: `/` returned 200, health `ok`, the
version line printed, `Config.Env` null, and the database survived a restart. Two more criteria
ticked, with the evidence in a comment on #122.
