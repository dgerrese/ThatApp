**The merge closed the issue but did not strip its label — and it had been happening for a week.**
#9 was found closed and still carrying `status:in-progress`, which the status rules call a lie
outright, since GitHub already records how an issue ended. Auditing the rest of the board found the
same on **#7 and #73**: every ticket merged since 2026-08-27. `Closes #<n>` closes the issue and
nothing removes the label, so the move belongs to a session — and the owner merging is exactly the
moment no session is watching. All three are stripped, and the board now audits clean: no closed
issue carries a `status:*` label, and every open one carries exactly one.

**The audit is two `gh` calls and is worth running at the start of any session that follows a
merge**, because a stale label is invisible from the issue itself:

```shell
gh issue list --state closed --limit 60 --json number,labels \
  --jq '[.[] | select([.labels[].name] | any(startswith("status:"))) | .number]'
gh issue list --state open --limit 60 --json number,labels \
  --jq '[.[] | select(([.labels[].name] | map(select(startswith("status:"))) | length) != 1) | .number]'
```

## 2026-09-01, later — the handoff was split into current state plus a file per day

`docs/superpowers/plans/2026-08-12-handoff.md` had reached 1655 lines / 124kB, and roughly a third
of it was dated narrative that every session paid to load and almost never needed. It is now
`docs/superpowers/plans/handoff.md` — current state only, 1114 lines — with the nine dated entries
carved into `docs/superpowers/plans/handoff/YYYY-MM-DD.md`, eight files.

**The split is by kind, not purely by date, and that was the whole argument.** Per-day files for
*current state* would have been a mistake: answering "what is still open" would mean reading every
day and reconciling them, and a decision taken on 08-14 and reversed on 08-27 would sit in two
files with nothing marking which wins. Editing one line wins. Per-day files for the *narrative* are
strictly better: nothing reads 08-22 once 09-01 exists, and two machines working different days can
no longer conflict — which is what the `2026-08-31` entry above records happening.

**The carve was mechanical and verified line-for-line.** Every `###` heading beginning with a date
moved out; everything else stayed. The only content that changed position: *What mutation testing
found*, *Decisions taken during #7's Go side* and *Decisions taken during #9* were stranded inside
the dated blocks and now sit under `## Decisions taken — do not reopen`, the section named for
