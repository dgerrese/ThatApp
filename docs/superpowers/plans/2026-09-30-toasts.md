# Toasts and dialog blocks Implementation Plan

**Date:** 2026-09-30
**Supersedes:** nothing
**Superseded by:** nothing

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Push and fetch reports and failed one-off actions become toasts, bottom-right; every message the entry dialog shows becomes a block above the dialog; state messages stay inline (#123).

**Architecture:** A `that-toasts` host element sits in `index.html` from first render (`role="status"`, `popover="manual"`, hidden while empty) and is upgraded from its own lazily loaded chunk, as `that-tooltip` is. Callers use `toast(tone, message, items?)` from `web/src/toast.ts`, which finds the host and calls its `add()`. Each toast is a `that-toast` element; its tone mark comes from a helper extracted from `that-alert`, so the tone rule stays in one place and no live region nests inside another. The entry dialog gets its own block host: a second manual popover positioned against the dialog's box.

**Tech Stack:** TypeScript, Tailwind CSS v4, Playwright (Firefox and Chromium).

**Spec:** `docs/superpowers/specs/2026-09-25-toasts-design.md` (the design, settled with the owner on 2026-09-25) and Codeberg issue #123 (its acceptance criteria). The design's companion screens are in `.superpowers/brainstorm/770361-1790339513/content/` (`q3-anatomy.html` is the anatomy drawing, `q4-dialog-blocks.html` the dialog blocks).

## Global Constraints

- All tooling through `make` or `docker compose`; never Go, Node or npm on the host.
- No JavaScript frameworks. Tailwind v4 utilities; light DOM, never shadow DOM. A reusable component is a `that-*` WebComponent.
- Initial HTTP response under 14kB: `index.html` gains only the empty host element; toast code loads in its own chunk.
- Firefox and Chromium only.
- **The wording of every message is unchanged.** A test that asserted a message's text inline asserts the same text in the toast or block.
- **The tone rule is unchanged:** the tone colours the mark only; the words are in ordinary ink; the mark carries `aria-label` "Done", "Warning" or "Failed".
- Anatomy (design doc table): surface `--color-raised`, radius 8px (`rounded-md`); shadow dark `0 2px 6px rgba(0,0,0,.45), 0 18px 40px -16px rgba(0,0,0,.7)`, light `inset 0 0 0 1px var(--edge), 0 6px 16px -8px rgba(0,0,0,.12)`; width 320px; padding `11px 12px 11px 14px`; row: 18px mark, 10px gap, message 14px/20px, list below at 13px in muted ink; close: the `close` icon at 16px in muted ink at the row's right end, a real `<button>` labelled "Dismiss"; countdown (success only): a 2px line 9px under the row, edge-tone track, muted-ink fill shrinking over the toast's life; stack 16px from the content area's right and bottom edges, 8px between toasts, newest at the bottom.
- A success toast leaves after about 4 seconds; the countdown pauses while the pointer or focus is on it and resumes where it paused. A warning or error never times out and survives moving between views.
- Do not run Prettier on `.claude/e2e/` (no config there). For `web/src`: `docker compose run --rm --no-deps web npx prettier --write <files>`.
- Commits: if `git commit` fails on signing, retry with `git -c commit.gpgsign=false commit …`. Never push.

## Rulings made before execution (the controller's, reversible)

1. **Settings failures are toasts, not dialog blocks.** The design predates #89 (Settings became a dialog). The acceptance criteria name the Settings remove failure and the save failure after the form closed as toasts, and a toast shows above an open dialog. Built as written; the question is parked on #123.
2. **No nested live regions.** `that-alert` sets its own `role="status"`. `that-toast` does not wrap a `that-alert` element; it builds the same row from a `toneMark()` helper extracted from `that-alert.ts`, so the tone rule stays single-sourced and only the host is a live region.
3. **The block host is its own top-layer popover**, positioned from the dialog's box, because a modal dialog clips its overflow and a child drawn above it would be cut off.
4. **The host is hidden while empty**, which keeps existing `getByRole("status")` locators unambiguous; it is shown before a toast's text is inserted.
5. **Tests whose premise was placement** keep asserting the same wording, now in the toast; only their placement assertions change, and each is listed in the task report.

## Review Focus

1. A toast added while the entry dialog or Settings is open must sit above the dialog and its backdrop, with a working Dismiss.
2. A warning toast must survive a route change (Today → Week → Today): the host lives outside `#view`.
3. Pausing: pointer over, then off; focus into the Dismiss button, then out. The countdown resumes from where it paused, not from the start.
4. A dialog block must follow the dialog when the dialog's height changes (the entry list loads after open, and the dialog is centred), and must leave with the dialog.
5. Existing `role="status"` locators (`table.spec.ts:748`, `settings.spec.ts:549`) must stay unambiguous.

```ts
/** The tone's mark: coloured, and named for when colour cannot carry it. Shared with that-toast. */
export function toneMark(tone: string): HTMLElement {
  const spec = TONES[tone] ?? TONES["warning"]!;
  const mark = document.createElement("span");
  mark.className = `shrink-0 leading-6 ${spec.colour}`;
  mark.innerHTML = iconMarkup(spec.icon);
  // The mark is decorative on its own account (icons.ts sets aria-hidden);
  // the word it stands for is not, so the wrapper carries it instead.
  mark.setAttribute("role", "img");
  mark.setAttribute("aria-label", spec.label);
  return mark;
}
```

- [ ] **Step 5: Write `web/src/components/that-toast.ts`**

```ts
import { iconMarkup } from "../icons";
import { toneMark } from "./that-alert";

/**
 * One toast (#123): that-alert's row — the tone's mark, the words in ordinary
 * ink — with its list, a Dismiss button, and, for a success, the countdown line
 * whose animation is the toast's life. Not a live region: the host is.
 * `block` is the dialog-block variant: sized by its host, and no countdown,
 * because a block leaves only when closed, retried or its dialog closes.
 */
export class ThatToast extends HTMLElement {
  items: string[] = [];

  connectedCallback(): void {
    if (this.childElementCount > 0) return;
    const tone = this.getAttribute("tone") ?? "warning";
    const block = this.hasAttribute("block");

    this.className =
      "bg-raised text-ink shadow-toast block rounded-md pt-[11px] pr-3 pb-[11px] pl-[14px] " +
      (block ? "w-full" : "w-[320px]");

    const row = document.createElement("div");
    row.className = "flex items-start gap-[10px] text-base leading-5";
    const mark = toneMark(tone);
    mark.classList.replace("leading-6", "leading-5");
    const message = document.createElement("span");
    message.className = "min-w-0 flex-1";
    message.textContent = this.getAttribute("message") ?? "";
    const dismiss = document.createElement("button");
    dismiss.type = "button";
    dismiss.setAttribute("aria-label", "Dismiss");
    dismiss.className =
      "text-ink-muted hover:text-ink focus-visible:text-ink -my-0.5 flex shrink-0 cursor-pointer items-center justify-center rounded-sm";
    dismiss.innerHTML = iconMarkup("close", 16);
    dismiss.addEventListener("click", () => this.dismiss());
    row.append(mark, message, dismiss);
    this.append(row);

    if (this.items.length > 0) {
      const list = document.createElement("ul");
      list.className = "text-ink-muted mt-2 ml-7 space-y-1 text-sm";
      for (const item of this.items) {
        const li = document.createElement("li");
        li.textContent = item;
        list.append(li);
      }
      this.append(list);
    }

    if (tone === "success" && !block) {
      const track = document.createElement("div");
      track.dataset["countdown"] = "";
      track.className = "bg-edge mt-[9px] h-[2px] overflow-hidden rounded-full";
      const fill = document.createElement("span");
      fill.className = "bg-ink-muted block h-full";
      fill.addEventListener("animationend", () => this.dismiss());
      track.append(fill);
      this.append(track);
    }
  }

  dismiss(): void {
    this.dispatchEvent(new Event("toast-dismissed", { bubbles: true }));
    this.remove();
  }
}

customElements.define("that-toast", ThatToast);
```

The list's text is 13px (`text-sm`); keys are printed as they come, and the design's "keys in Chivo Mono" is honoured only if an item is a key alone — do not split items. Check `bg-edge` and `text-sm` resolve to `--color-edge` and 13px; if a token name differs, use the existing one.

- [ ] **Step 6: Write `web/src/components/that-toasts.ts`**

```ts
import "./that-toast";
import type { ThatToast } from "./that-toast";

/**
 * The toast stack (#123): one host, in the markup from first render so the
 * live region exists before any message does, and a manual popover so it can
 * sit in the top layer. A dialog opened with showModal() is in the top layer
 * too, and makes the rest inert — so while one is open the host is re-shown on
 * every add, which puts it last in the top layer and above the dialog.
 * Hidden while empty.
 */
export class ThatToasts extends HTMLElement {
  connectedCallback(): void {
    this.addEventListener("toast-dismissed", () => {
      queueMicrotask(() => {
        if (this.childElementCount === 0 && this.matches(":popover-open")) this.hidePopover();
      });
    });
  }

  add(tone: string, message: string, items: string[] = []): HTMLElement {
    if (this.matches(":popover-open") && document.querySelector("dialog:modal")) this.hidePopover();
    if (!this.matches(":popover-open")) this.showPopover();

    const toast = document.createElement("that-toast") as ThatToast;
    toast.setAttribute("tone", tone);
    toast.setAttribute("message", message);
    toast.items = items;
    this.append(toast);
    return toast;
  }
}

customElements.define("that-toasts", ThatToasts);
```

```ts
export type Tone = "success" | "warning" | "error";

/**
 * Shows a toast (#123). The host is in index.html from first render and is

export function toast(tone: Tone, message: string, items: string[] = []): void {

    const host = document.querySelector("that-toasts") as
      | (HTMLElement & { add(tone: string, message: string, items: string[]): HTMLElement })

    host?.add(tone, message, items);
  });
}
```
