**Goal:** One server-side timer per user, started and stopped from a Today row or the rail, that creates an honest time entry when it stops and closes itself at local midnight.

**Architecture:** The store owns the rules: at most one timer, stop creates an entry, under 60 s creates nothing, and a timer is capped at local midnight of its start day. Every rule lives in one transaction-scoped helper. Three thin HTTP endpoints expose them. The browser keeps one `timer-state` module (read once, re-read after each start or stop, and ticking each second only while running), a `that-timer` play/stop button per row, and the rail's running line with its stop.

**Tech Stack:** Go standard library (`database/sql`, `modernc.org/sqlite`), TypeScript, light-DOM WebComponents, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-18-timer-design.md` (the design, with the owner's decisions), and issue #8's acceptance criteria (`tea api "repos/{owner}/{repo}/issues/8"`). **Read both before any task.**

- **The day boundary is `THAT_TIMEZONE` (`cfg.Location`), never the machine's zone.** Every store call takes `now` and `loc`; nothing in the store reads the clock for timer logic.
- Decisions, verbatim from the design: **under 60 s → no entry** (a stop or switch reports `discarded`); **a timer from a previous local day is closed by the server at local midnight of its start day on any read**; an entry's `started_at` is the timer's start and its `day` the start's local date.

### Task 1: The store keeps one timer and turns it into an entry

**Files:**
- Create: `internal/store/timers.go`, `internal/store/timers_test.go`
- Modify: `internal/store/entries.go` (extract the INSERT from `CreateEntry` into `insertEntry(ctx, q execer, in EntryInput) (*Entry, error)`, where `execer` is the `ExecContext` method set shared by `*sql.DB` and `*sql.Tx`; `CreateEntry` calls it with `s.db`)

**Interfaces — produces:**
```go
type Timer struct {
	InstanceID int64
	IssueKey   string
	StartedAt  time.Time // UTC, second resolution
}

// MinTimerSeconds: a run shorter than this leaves no entry (Jira rejects worklogs under a minute).
const MinTimerSeconds = 60

func (s *Store) RunningTimer(ctx context.Context, now time.Time, loc *time.Location) (running *Timer, closed *Entry, err error)
func (s *Store) StartTimer(ctx context.Context, instanceID int64, issueKey string, now time.Time, loc *time.Location) (running *Timer, stopped *Entry, err error)
func (s *Store) StopTimer(ctx context.Context, now time.Time, loc *time.Location) (stopped *Entry, wasRunning bool, err error)
```
- `RunningTimer`: if the timer's start (in `loc`) is on an earlier local date than `now` (in `loc`), close it (capped at the start day's local midnight; a run under 60 s leaves no entry), delete it, and return `(nil, entry-or-nil, nil)`. Otherwise return the timer. It does all of that in one transaction.
- `StartTimer`: in one transaction, close any running timer at `min(now, cap)` (same rules), then insert the new one. Keep `CHECK (id = 1)` intact: always write `id = 1`. An `instanceID` with no row surfaces the foreign-key failure as `ErrInstanceNotFound` if the store has such a sentinel, otherwise as a wrapped error that the handler maps to 404 — read `pins.go` / `entries.go` in the store for the existing convention and follow it.
- `StopTimer`: nothing running → `(nil, false, nil)`. Otherwise it closes (same rules) and deletes in one transaction and returns `(entry-or-nil, true, nil)`.
- Close rule, one private helper used by all three: `end = min(now, localMidnightAfter(startDay))`; `seconds = int(end.Sub(start) / time.Second)`; `seconds < MinTimerSeconds` → no entry. Otherwise `insertEntry` with `Day = start.In(loc).Format("2006-01-02")`, `StartedAt = start`, `Seconds = seconds`, `Comment = ""`.

### Task 2: `/api/timer`, `/api/timer/start`, `/api/timer/stop`

**Files:**
- Create: `internal/server/timer.go`, `internal/server/timer_test.go`
- Modify: `internal/server/server.go` (three routes)

**Interfaces:**
- Consumes: Task 1's store methods; the existing entry DTO renderer in `entries.go` (`s.entryDTOFrom` or whatever it is named — reuse it, do not re-render entries).
- Produces (JSON):
  - `GET /api/timer` → `200 {"running": null | {"instanceId","issueKey","startedAt"}, "stopped": null | <entry DTO>}`. `stopped` is non-null only when this read closed a timer at midnight.
  - `POST /api/timer/start` with `{"instanceId": number, "issueKey": string}` → `200 {"running": {...}, "stopped": null | <entry DTO>}`. Blank or missing key or malformed body → `400 invalid_request`; unknown instance → `404 instance_not_found`.
  - `POST /api/timer/stop` → `200 {"stopped": null | <entry DTO>, "discarded": bool}`. `discarded` is true when a timer was running but its run was under a minute.
  - `startedAt` is RFC3339 in `cfg.Location` (as `/api/entries` renders `startedAt`).
- Handlers pass `s.now()` and `s.cfg.Location` to the store.

### Task 3: Start and stop from a row and from the rail

**Files:**
- Create: `web/src/timer-state.ts`, `web/src/components/that-timer.ts`

- Test: `.claude/e2e/tests/timer.spec.ts` (new)

**Behaviour (from the design):**
- `timer-state.ts`: `readTimer()` (GET), `startTimer(instanceId, key)`, `stopTimer()`, `currentTimer(): RunningTimer | null`, `onTimerChanged(handle): () => void` (the unsubscribe), and a single `setInterval(…, 1000)` that runs only while a timer runs and notifies subscribers with the elapsed time. Any response carrying a `stopped` entry calls `announceEntriesChanged()` from `entries-changed.ts`. A stop answering `discarded: true` shows "Under a minute — nothing logged." once, in the same place push reports appear (read how `push-report.ts` / `push-reported.ts` surface a report and reuse that path; if no path fits, stop and report rather than inventing a new surface).
- `that-timer`: attributes `instance-id`, `key`. It renders a 34 px `iconbtn` (the pin's class list) with the play icon and aria-label "start timer", or with the stop icon, aria-label "stop timer" and the running tone (`text-running`), when `currentTimer()` is this ticket. It starts or stops on click, and subscribes in `connectedCallback` and unsubscribes in `disconnectedCallback`.
- `that-ticket-row`: puts a `that-timer` before the pin in `c-act`. While its ticket runs, the key wears `text-running` and the Today figure shows logged + elapsed in `text-running`, ticking. When the timer stops, it returns to its `seconds` attribute, which the entries refresh then updates. Repaint only those cells, as the row already does for `seconds`.
- Rail: `#rail-timer` shows "No timer running" (as today) or the running line: a dot in `bg-running-rail`, the key, the elapsed time right-aligned in mono in `text-running-rail`, and a stop button (the stop icon, aria-label "stop timer", `text-running-rail`, the rail's hover wash `hover:bg-hover-rail` or its existing equivalent). Elapsed format: `M:SS` under an hour, `H:MM:SS` from an hour on. The rail reads the timer at start-up via `readTimer()`.
- Tokens: use the existing `running` and `running-rail` tokens in `web/src/styles.css`. If a class you need has no token, stop and report — do not add raw colours.
