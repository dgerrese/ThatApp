# Playwright 1.63.0 for the e2e rig (#134) Implementation Plan

**Date:** 2026-09-21
**Supersedes:** nothing
**Superseded by:** nothing

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** A full local `make test-e2e` run stops crashing Chromium, so a red run means something.

**Architecture:** One dependency bump. `.claude/e2e/package.json` pins `@playwright/test` at
1.63.0, `package-lock.json` is regenerated to match, and `.claude/e2e/Dockerfile` installs the
matching browsers on its next build because it already runs `npx playwright install` from that
lockfile. No source, test or workflow file changes.

**Tech Stack:** npm, Playwright, the Compose e2e profile.

**Spec:** Codeberg issue #134 — `tea api "repos/{owner}/{repo}/issues/134"`.

## What is already known, and must not be re-derived

Measured on 2026-09-21 against `main` at `b623295`, on this machine:

| Playwright | full runs | crashes |
|---|---|---|
| 1.62.1 | 20 | 5 (25%) |
| 1.63.0 | 30 | 0 |

The 1.62.1 figure includes a ten-run control taken *after* the clean sample, which crashed three
times — the version is the variable, not the machine. All five crashes were byte-identical:
`SEGV_MAPERR 0x1b0` in the browser process inside `browser.newContext`, same stack offsets.

**The suite passes unchanged on 1.63.0**: 513 passed, 11 skipped, no API migration and no test
edits. That was verified by running the real suite against 1.63.0, not inferred.

**Do not** cap worker count, change `retries`, skip or quarantine a test, or touch `ipc: host`.
Those are named out of scope on the ticket.

## Global Constraints

- No Go, Node or npm on the host; everything runs through `make` or `docker compose`.
- The owner's dev stack (`app`, `web`) is theirs: never `make down`, never stop or recreate it.
- **`npx playwright install` prunes browser builds the running version does not use.** A container
  that installs 1.63's browsers loses 1.62.1's. This bites only if you try to A/B inside one
  container — the plan does not, and neither should you.
- Comments are few and explain a non-obvious why.
- Commit unsigned with `git -c commit.gpgsign=false commit …` if signing fails; **never push**.

### Task 1: Bump Playwright and prove the crash is gone

**Files:**

**Interfaces:** none shared with other tasks.

- [ ] **Step 1: Record the RED that already exists**

The failing evidence for this ticket is a crash rate, not an assertion, and it has already been
measured at 25% over twenty runs (see the table above). Do **not** spend twenty runs reproducing it.
Quote the recorded measurement as RED in your report, and cite the ticket.

- [ ] **Step 2: Bump the pin**

In `.claude/e2e/package.json`, change `"@playwright/test": "1.62.1"` to `"1.63.0"`. Regenerate the
lockfile through the container so the host needs no npm:

```shell
docker compose --profile e2e run --rm --no-deps playwright npm install --package-lock-only --no-audit --no-fund
```

Confirm `package-lock.json` now resolves `@playwright/test` at 1.63.0, and that **no other
dependency moved** — `git diff` the lockfile and say so in your report. A bump that quietly drags
other packages is a different change and must be reported, not absorbed.

- [ ] **Step 3: Rebuild the rig image**

The Dockerfile installs browsers at build time, so the image must be rebuilt or the container will
run 1.63.0's test runner against 1.62.1's browsers:

```shell
docker compose --profile e2e build playwright
```

- [ ] **Step 4: GREEN — twenty consecutive full runs**

The ticket's acceptance criterion. Run the full suite twenty times and record every result:

```shell
for i in $(seq 1 20); do
  docker compose --profile e2e run --rm playwright npx playwright test > /tmp/run-$i.log 2>&1
  printf 'run %s: exit=%s crash=%s | %s\n' "$i" "$?" \
    "$(grep -qE 'SEGV_MAPERR|Target page, context or browser has been closed' /tmp/run-$i.log && echo yes || echo no)" \
    "$(grep -oE '[0-9]+ (passed|failed)' /tmp/run-$i.log | tr '\n' ' ')"
done
```

**Every run must show `crash=no`.** A single `SEGV_MAPERR` fails the task — report it rather than
re-running, because the whole point of the ticket is that a red run means something.

Each run takes roughly 70 seconds, so budget about 25 minutes. Paste the twenty summary lines into
your report verbatim; they go into the pull request body.

- [ ] **Step 5: Confirm the pass count is unchanged**

Every run must report the same counts as 1.62.1 on the same base. A lower pass count means a test
was skipped rather than fixed, which the ticket forbids.

**The number moved on 2026-09-21 and the original figure here was stale.** This plan was written
against `main` at `b623295`, where the suite was **513 passed / 11 skipped**. Twelve pull requests
then merged, adding tests (#57, #102, #35, #116, #71), and on `2399fe8` the suite is
**526 passed / 14 skipped / 0 failed**. Take the count from a run on your own base rather than from
a number written down earlier.
