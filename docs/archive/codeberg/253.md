# CB#253: An MCP server, so an AI assistant can read and log time through the app

Archived from Codeberg issue [#253](https://codeberg.org/DionGerrese/ThatApp/issues/253), closed. Opened by DionGerrese on 2026-09-28, closed on 2026-10-07.

Labels: `enhancement`.

Milestone: v1.

**Why it is kept:** MCP server decisions not in any spec: no push tool (an assistant never writes to Jira), stdlib hand-written JSON-RPC, Origin check as the only protection, no token or THAT_* variable, dual-era protocol support, delete_entry refusal until CB#280.

## Body

Asked for by the owner on 2026-09-28. Refined with the owner on 2026-10-06.

#### Problem

An MCP (Model Context Protocol) client — Claude Code, Claude Desktop, another assistant — cannot work with ThatApp's data except through the browser. The owner wants an assistant to read what is assigned and logged, and to log time, through tools.

#### Decisions, settled with the owner on 2026-10-06

- **Tools: read, entries and timer. No push.** Worklogs reach Jira only from the app's own Push button, so an assistant can never write to a real Jira instance.
- **Transport: Streamable HTTP at `/mcp`**, served by the existing Go server. Stateless: every request is a JSON-RPC POST answered with `application/json`; no session, no server-sent event stream. A client connects with `claude mcp add --transport http thatapp http://localhost:<THAT_PORT>/mcp`.
- **Standard library only.** The protocol is hand-written JSON-RPC: `initialize`, `ping`, `tools/list`, `tools/call`, and notifications accepted with `202`. The approved dependency set does not change.
- **Protection: the `Origin` check, and nothing else.** `/mcp` rejects any request carrying an `Origin` header with `403`, which the MCP specification asks for against DNS rebinding: a browser always sends one, an MCP client sends none. This is the same trust boundary `/api/*` has today. No token and no new `THAT_*` variable; real authentication stays with the deferred LAN and HTTPS ticket.
- **An open tab catches up when it regains focus.** The rail reads the timer once, at page load, so a timer started through MCP would otherwise stay invisible in an open tab until a reload. The app re-reads the timer and the current view's entries when the tab becomes visible or the window regains focus — the usual case is asking the assistant in a terminal, then switching back to the browser. Related, not replaced: CB#207 and CB#226 handle a stale tab's failed start and stop.

- **Decided with the owner on 2026-10-07.** The server is **dual-era**: it serves MCP 2026-07-28 without state, and it still answers `initialize` for 2025-11-25 and older. **`delete_entry` refuses an entry that already has a Jira worklog**, so an assistant never writes to Jira. Remove that check when CB#280 lands: CB#280 makes a delete of a pushed entry wait for Push.

#### Approach

**Each tool is a thin call to the existing `/api/*` handler, in process.** A tool builds the request the browser would send, runs it through the server's own mux, and returns the response body as the tool result — `isError: true` when the status is 4xx or 5xx, with the API's error message as the text. Nothing is reimplemented, so an entry made through MCP resolves its day against `THAT_TIMEZONE`, is validated, and gets its derived push state exactly like one made in the browser. A later change to a handler reaches the tool without touching it.

| Tool | Calls | Arguments |
|---|---|---|
| `list_issues` | `GET /api/issues` | — |
| `search_issues` | `GET /api/issues/search` | `q` |
| `list_entries` | `GET /api/entries` | `from`, `to` (optional, `YYYY-MM-DD`, default today) |
| `get_week` | `GET /api/week` | `start` (optional, default this week's Monday) |
| `get_timer` | `GET /api/timer` | — |
| `create_entry` | `POST /api/entries` | `instanceId`, `issueKey`, `day`, `seconds`, `comment` |
| `update_entry` | `PATCH /api/entries/{id}` | `id`, `seconds`, `comment` (each optional) |
| `delete_entry` | `DELETE /api/entries/{id}` | `id` |
| `start_timer` | `POST /api/timer/start` | `instanceId`, `issueKey`, `round`, `comment` |
| `stop_timer` | `POST /api/timer/stop` | `round`, `comment` |

Each tool's `inputSchema` and description say what the API's own request type accepts, including that `day` and the timer's start are resolved in the server's timezone.

#### Acceptance criteria

- [x] `POST /mcp` answers `initialize` with the server's name, version and the `tools` capability, negotiating the protocol revision current when built.
- [x] `tools/list` returns exactly the ten tools above, each with a description and a JSON Schema for its arguments.
- [x] Each tool's `tools/call` reaches its `/api/*` handler and returns that handler's JSON body; a 4xx or 5xx comes back as `isError: true` carrying the API's message, never as a JSON-RPC protocol error.
- [x] No tool pushes, fetches from Jira for the week, or touches instances or pins; `tools/call` for any other name is a JSON-RPC error.
- [x] An entry created through `create_entry` near midnight UTC lands on the `THAT_TIMEZONE` day, proven by a table-driven test that a plausible refactor would fail.
- [x] No tool can set push state: an entry edited through `update_entry` after a push reads as dirty, exactly as through the API.
- [x] A request carrying any `Origin` header gets `403` and reaches no handler.
- [x] `GET /mcp` answers `405`; a notification answers `202` with no body; malformed JSON and an unknown method get the JSON-RPC error codes the specification names.
- [x] Tests run against the handlers with `httptest`; no test contacts a real Jira instance.
- [x] Each new or changed assertion is proven by mutation.
- [x] With the app open on Today, a timer started and an entry created outside the tab (through the API, standing in for MCP) appear in the rail and in Today when the tab becomes visible again, without a reload. The same holds for Week's entries.
- [x] A tab that stays visible and focused makes no extra reads.
- [x] The README says how to connect Claude Code to `/mcp`, and that it carries the same no-login warning as the port.
- [x] `make verify` is green.

#### Out of scope

- Push, the week's Jira fetch, instances and pins — declined on 2026-10-06.
- Authentication beyond the `Origin` check — deferred with LAN and HTTPS.
- A stdio transport, sessions, server-sent events, resources and prompts.
- Live updates to a tab that stays visible while an MCP write happens — no push channel from server to browser.
