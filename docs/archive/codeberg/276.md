# CB#276: Closing an issue does not remove its status/* label

## Body

Found by the 2026-10-05 retro.

#### Problem

A merged pull request closes its issue through `Closes #<n>`, but the issue keeps `status/in-progress`. The rules say a closed issue carries no `status/*` label, so every merge needs a hand fix. The handoff records about 60 occurrences since 2026-08-28, and it happened again on CB#123 on 2026-10-05.

The merge is the owner's action and the label strip is the session's, and nothing connects the two. A process rule can only make the session sweep up afterwards.

#### Idea

A Forgejo Actions workflow on `issues: [closed]` that removes every `status/*` label from the closed issue. The forge then does it at the moment of the close, and no session has to notice.

Not confirmed: whether the workflow's default token may edit issue labels on Codeberg, and whether a hosted runner picks up an `issues` event.
