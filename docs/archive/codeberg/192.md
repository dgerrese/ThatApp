# CB#192: A row that a sort moves loses its start/stop button

Archived from Codeberg issue [#192](https://codeberg.org/DionGerrese/ThatApp/issues/192), closed. Opened by DionGerrese on 2026-09-23, closed on 2026-09-23.

Labels: `bug`, `priority/high`.

Milestone: v1.

**Why it is kept:** Bug investigation with root cause: the moveBefore/insertBefore reconnect rebuilds that-timer's button while the renderedMine memo claims it is drawn; why both fixes are needed is only half in code comments.

## Body

Asked for by the owner on 2026-09-23. Found in PR CB#190's screenshot, where a moved row shows no
start/stop button. Refined with the owner the same day.

#### Problem

A row that a sort moves loses its start/stop button. It dates from CB#8 meeting [CB#83](83.md); [CB#183](183.md) makes it
easier to reach, because a running timer now moves its row.

`that-table`'s `reorder()` moves rows with `moveBefore`. `that-ticket-row` opts in with a no-op
`connectedMoveCallback`, but `that-timer` inside it does not, so the move disconnects and reconnects
the timer. Its `connectedCallback` calls `render()`, which builds a new, empty trigger button. That
calls `paint()`, which returns early because `renderedMine` still holds the value it drew on the old
button. The new button stays empty.

The `insertBefore` fallback (Firefox ESR before 144) reconnects every row anyway, so it reaches the
same early return.

#### Approach

Two changes in `web/src/components/that-timer.ts`, and both are needed:

1. **`render()` clears `renderedMine` before it calls `paint()`.** A new button has nothing drawn on
   it, so the memo must not claim otherwise. This is the root-cause fix and covers every reconnect,
   including the `insertBefore` path.
2. **A no-op `connectedMoveCallback()`**, as `that-ticket-row` has. With `moveBefore` the button node
   then survives the move, so a focused button keeps focus. Alone it would leave the `insertBefore`
   path broken, which is why (1) is not optional.

No dependency on PR CB#190: a column sort moves a row without [CB#183](183.md).

#### Acceptance criteria

- [x] After a sort moves a row, its `that-timer` button shows the right icon and `aria-label`
      (start or stop), in Firefox and Chromium. Covered by an e2e test.
- [x] A `that-timer` that is disconnected and reconnected — the `insertBefore` path — draws its
      button again. Covered by a test; e2e is acceptable, since the unit suite has no DOM until CB#91
      adds happy-dom.
- [x] With `moveBefore`, a focused start/stop button keeps focus when a sort moves its row.
- [x] The pull request attaches a screenshot of a moved row with its button, per the screenshot rule.
- [x] `make verify` and `make test-e2e` are green.

#### Out of scope

- Any other element inside a row that lacks `connectedMoveCallback`. None is known; one found is an
  intake ticket.
