# CB#204: A running timer's elapsed time is missing from the card tally and the rail total

Archived from Codeberg issue [#204](https://codeberg.org/DionGerrese/ThatApp/issues/204), closed. Opened by DionGerrese on 2026-09-23, closed on 2026-09-28.

Labels: `bug`.

Milestone: v1.

**Why it is kept:** Owner decision that running time counts on the Today period only, while Week's rail total keeps matching the grid footer; push count stays entries-only; accepted ceilings (dip at stop, run past midnight) are not in any spec.

## Body

Found by the [CB#183](183.md) build (PR CB#190), 2026-09-23.

#### Problem

While a timer runs, its row shows logged time plus elapsed time, but the card's tally ("2 issues · 1h 59m") and the rail's day total show logged time only. So the running row's figure and the totals above it disagree for as long as the run lasts. Visible in PR CB#190's screenshot: WORK-2 reads 1:01 while the rail and tally read 1h 59m. Pre-existing; [CB#183](183.md) made the row and the sort agree, not the totals.

**Settled by the owner on 2026-09-25:** the running time counts on the Today period only (Today and Settings). On Week, the rail's week total keeps matching the grid's footer beside it.

#### Approach

- **Card tally** (`paintInstanceTallies` in `web/src/views/today.ts`): add `elapsedSeconds()` to the tally of the instance whose id matches `currentTimer()`'s `instanceId`, wherever the running row sits, pinned included — the tally counts the instance's whole day. Subscribe `onTimerChanged` at mount with `registerTeardown`, and repaint the tallies from `regions.totals`.
- **Rail** (`rail.ts`): `paint` keeps the last entries. On the Today period, a total-and-split paint adds `elapsedSeconds()` to the total and to the running instance's slice, driven by `onTimerChanged` as well as by entries. On Week it does not.
- A slice for an instance with no entries yet needs a name and position, so `GET /api/timer`'s running DTO (`internal/server/timer.go`, `RunningTimer` in `types.ts`) gains `instanceName` and `instancePosition`, the fields the entries DTO already carries.
- **Cadence:** keep the existing 1-second tick. Both figures floor to whole minutes through `totalFigure`, so a repaint writes only when the text changes — in practice once a minute.
- **Unchanged:** the unpushed count, the push button's enabled state and the push confirmation's total stay entries-only, because elapsed time is not an entry. The totals keep their ink colour; the running tone stays reserved for the timer and its stop control.
- **Accepted ceiling:** at stop, `setRunning(null)` fires before the entries re-read lands, so the totals dip for one request before showing the rounded entry — as the row's figure already does. A browser left open across midnight counts the run's time after midnight until a read closes it.

#### Acceptance criteria

- [ ] While WORK-2 runs, on Today, the rail total, the running instance's split figure and that instance card's tally each equal logged time plus elapsed, to the minute. All three move when the run crosses a minute (clock advanced with `page.clock`).
- [x] The running instance gets a split slice even when it has no entry yet today.
- [x] On Week, the rail's total equals the grid footer's total while a timer runs.
- [x] Across the run, "N entries to push" and the push dialog's total are unchanged.
- [ ] After a stop, the figures equal the logged time plus the rounded entry.
- [x] The tick does not rebuild the split's DOM more than once per minute (asserted, e.g., through a node identity that holds across ticks within one minute).
- [x] A Go handler test covers the new `instanceName`/`instancePosition` fields on `GET /api/timer`.
- [ ] The PR carries a dark and light screenshot pair; `make verify` and `make test-e2e` are green.

#### Out of scope

- The Week grid's cells and footer, which have no live figure (as in [CB#183](183.md)).
- The dip at stop, and the run's time after midnight in a tab left open overnight.
