# CB#74: `make fmt` rewrites seven committed files: prettier formatting is gated by nothing

Archived from Codeberg issue [#74](https://codeberg.org/DionGerrese/ThatApp/issues/74), closed. Opened by DionGerrese on 2026-09-01, closed on 2026-09-24.

Milestone: v1.

**Why it is kept:** Owner chose 'format once, then check' over pinning prettier exactly (lockfile already pins it) and over dropping make fmt; the rejected options and reasons are not in the prettier-gate plan or elsewhere.

## Body

#### What happens

On a clean checkout of `main`, `make fmt` modifies seven files that are already committed:

```
web/index.html             | 47 ++++++++++++++++-----------
web/src/duration.test.ts   |  6 +++++-
web/src/duration.ts        |  3 +--
web/src/entries-changed.ts |  4 +++-
web/src/sw.ts              |  4 +++-
web/src/views/settings.ts  |  9 ++++++++-
web/src/views/today.ts     |  (also rewritten)
```

The changes are pure prettier reflowing — joining wrapped expressions back onto one line, and a
larger reflow of `index.html`. Nothing semantic.

#### Why it went unnoticed

**No gate checks formatting.** `web/package.json` defines:

- `"lint": "eslint src"` — eslint only, and it does not run prettier
- `"fmt": "prettier --write ..."` — write-only; there is no `prettier --check` anywhere

`make verify` is `lint tsc test`, so formatting is never asserted in CI or locally. The committed
tree can drift from what the toolchain produces and nothing notices.

**The drift has a plausible cause.** `prettier` is pinned as `^3.0.0` — a caret range —
and currently resolves to **3.9.6**. The committed formatting appears to predate a formatting change
in some 3.x release, and nobody has run `make fmt` since the lockfile moved.

#### Why it matters

Anyone who runs `make fmt` — which the Makefile advertises — gets seven unrelated files in their
diff and has to notice and revert them. That happened while working CB#73: the formatting churn
arrived mixed into an unrelated branch and had to be picked out by hand.

#### Settled at refinement (2026-09-23)

**Format once, then check it.** Chosen by the owner over pinning prettier exactly and over dropping
`make fmt`.

- **An exact pin adds little.** `web/package-lock.json` already fixes prettier at 3.9.6, and
  `npm ci` installs from the lockfile, so the formatter moves only when the lockfile moves. The gap
  is that nothing notices when it does.
- **The check goes in the npm `lint` script**, next to eslint, as `prettier --check` over the same
  globs `fmt` writes. `make lint` and CI's verify job both run `npm run lint`, so there is one
  definition and nothing for the two to drift over.
- **The reformat is its own commit**, holding nothing but prettier's output, so a reviewer can
  check it by re-running `make fmt` rather than by reading it.
- **The reformat conflicts with every open branch that touches a reformatted file.** The pull
  request lists the open branches it conflicts with, so the owner can choose when to merge it.

#### Acceptance criteria

- [x] On a clean checkout of the branch, `make fmt` leaves `git status --short` empty.
- [x] `npm run lint` runs `prettier --check` over the same globs as `npm run fmt`, and fails on
      an unformatted file. The pull request shows that failure once, on a deliberately unformatted
      file that is not committed.
- [ ] CI's verify workflow runs the check with no change to `.forgejo/workflows/verify.yml`, or the
      pull request changes that file to match, per the rule that CI and Compose are kept equal by
      hand.
- [x] The reformat is one commit with no change except prettier's output; `make verify` passes on
      it alone.
- [x] The check does not read built or installed files (`dist/`, `node_modules/`).
- [x] The pull request lists the open branches its reformat conflicts with.
- [x] `make verify` is green.

#### Out of scope

- Go formatting. `golangci-lint fmt` is a separate question and has no reported drift.
- Changing prettier's version or its configuration in `web/.prettierrc.json`.

#### How to reproduce

```shell
git checkout main && git status --short   # clean
make fmt
git status --short                        # seven modified files
```
