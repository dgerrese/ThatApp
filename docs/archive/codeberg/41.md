# CB#41: An instance with neither URL reports an unexpected error

Milestone: v1.

**Why it is kept:** Declined bug (wontfix): owner's 2026-09-18 comment explains why ErrInstanceNeedsURL is unreachable (NormalizeSiteURL, store validate, migration from NOT NULL base_url); not recorded in any living document.

## Body

`store.ErrInstanceNeedsURL` has no case in `instanceErrorFor` (`internal/server/instances.go`), so it falls to the `default` branch: the user sees "an unexpected error occurred" and the server logs it as unexpected on every request.

The message is unactionable — the fix is to add a site URL in Settings — and because the Today view refetches on every render and on every Refresh, the log line repeats each time.

A case returning something like `instance_needs_url` with a message naming the fix would close both. It introduces a code the Settings view does not render yet, which is why it was not folded into CB#5.
