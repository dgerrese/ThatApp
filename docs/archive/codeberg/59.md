# CB#59: The pin flow's canvas source contradicts CB#44's spec

Archived from Codeberg issue [#59](https://codeberg.org/DionGerrese/ThatApp/issues/59), declined (`wontfix`). Opened by DionGerrese on 2026-09-01, closed on 2026-09-02.

Labels: `wontfix`.

**Why it is kept:** Declined with no recorded reason; records that the still-committed pin-flow canvas (pinning-in-hybrid.html, which its README calls 'the visual language') contradicts CB#44's spec on ink-faint text and magenta keys, which no living doc warns about.

## Body

`docs/superpowers/canvas/2026-08-20-pin-flow/pinning-in-hybrid.html` is the approved look for the pin flow, but it predates CB#44's contrast measurements and disagrees with the visual language spec in two places: it uses `ink-faint` for headings and hint text, which fails the 4.5:1 text floor, and magenta issue keys, which CB#44 reserved for state so CB#8 and CB#9 can tint a key running-green and failed-red.

CB#6 did not inherit either mistake — its plan was written in the corrected vocabulary — so nothing shipped wrong. But the file is a design source a later ticket will read as authoritative, and it currently contradicts the spec that governs it.
