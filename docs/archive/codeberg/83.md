# CB#83: Sort the assigned issue listing on any displayed column

Archived from Codeberg issue [#83](https://codeberg.org/DionGerrese/ThatApp/issues/83), closed. Opened by DionGerrese on 2026-09-02, closed on 2026-09-22.

Labels: `enhancement`, `priority/high`.

Milestone: v1.

**Why it is kept:** Owner decisions not recorded elsewhere: per-table sort state overruling the 2026-09-03 shared-state call, Status sorted alphabetically with workflow-category ordering declined, and the three-step cycle rationale.

## Body

#### The ask

Sort Today's ticket tables on every displayed column.

#### What exists

Today renders three kinds of `that-table`: the **Pinned** card, the **Off-list** card, and one card
per **Jira instance**. CB#95 and [CB#117](117.md) gave every one of them a header row: Key, Summary, Status and
Today are each a `button` carrying the label and the `sortable` chevron at 45% opacity
(`web/src/components/that-table.ts`). The buttons have no click handler. Rows arrive in Jira's order,
`ORDER BY updated DESC` (`internal/jira/search.go`), and the app holds the whole assigned set, not a
first page, so a client-side sort sorts everything.

#### Decisions

The surface was settled in the design session of 2026-09-03 (see the comment below). The rest was
settled with the owner on 2026-09-18:

- **Every table sorts independently.** Pinned, Off-list and each instance card keep their own sort
  state. This **overrules** the 2026-09-03 comment's "one shared sort state applies to every card".
  Sorting still happens within a table, never across instances, so each card keeps its subtotal.
- **The click cycle has three steps.** The first click sorts in the column's natural direction:
  Key, Summary and Status ascending, and Today with the most time first. The second click reverses
  it. The third returns to Jira's order. Clicking a different column starts that column's cycle.
- **Status sorts alphabetically.** The app holds only the status name. Workflow-category ordering
  would widen this into the Go client and `/api/issues`, and was declined.
- **A table's sort survives a reload.** It is kept in `localStorage` per table: Pinned, Off-list,
  and each instance by its id. If storage is unavailable or holds something unreadable, the table
  falls back to Jira's order, and nothing breaks.

#### The ascending arrow, settled 2026-09-18

Settled in a browser design session: **the descending arrow, mirrored** (`M12 19.5V5M6.4 10.6 12
5l5.6 5.6`). It pairs with the drawn `#p-desc` and needs no new geometry. The owner chose it over an
up arrow with a baseline bar.

#### Acceptance criteria

- [x] Clicking Key, Summary, Status or Today sorts that table's rows by that column. The cycle is
      natural → reversed → Jira's order, and the natural direction is ascending for Key, Summary and
      Status and most-time-first for Today.
- [x] Key sorts by project, then numerically by issue number, so `RIDGE-9` comes before `RIDGE-10`.
      Summary and Status compare case-insensitively.
- [x] Rows that tie keep their relative Jira order, because the sort is stable.
- [x] Each table's sort is independent. Sorting one instance card leaves Pinned, Off-list and the
      other instance cards unchanged.
- [x] The sorted column's header shows the ascending or descending arrow and goes to full ink. Every
      other header shows the `sortable` chevron at rest. The state is not carried by the icon alone,
      and the button exposes it to assistive technology (`aria-sort` on the header cell).
- [x] The ascending arrow is the mirrored descending arrow settled above. The prototype gains it,
      and the build matches the drawing. The report says what was compared and what was found.
- [x] A table's sort survives a reload, in `localStorage` per table. Storage that is missing,
      blocked or unreadable falls back to Jira's order without an error.
- [x] A sorted table stays sorted when its rows change: a refresh, a pin or unpin, or time logged
      against a row, which moves it within the Today sort.
- [x] Unit tests cover the comparators and the cycle. An end-to-end test on Firefox and Chromium
      clicks through the cycle on one table and checks that another table is untouched.
- [x] `make verify` and `make test-e2e` are green.

#### Out of scope

- Sorting across instances, or any filtering or grouping control.
- Showing `updated` as a column.
- The Week view's grid.
- Workflow-category ordering for Status.

#### Dependencies

Touches the same rows as CB#8's timer.
